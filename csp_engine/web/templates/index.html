A Generic Constraint Satisfaction Engine

One solver, many problems — search, constraint propagation and heuristics for classical AI problem solving.

The one constraint this whole engine is built on

Six problems on this page — N-Queens, map colouring, Sudoku, cryptarithmetic, the Zebra logic puzzle, and exam timetabling — look unrelated. They are not. Every one of them is handed to the identical, untouched solver as the same mathematical object:

CSP = (Variables X, Domains D, Constraints C) a Constraint is nothing but: is_satisfied(assignment) -> bool "a boolean predicate over a tuple of variables"

The solver (backtracking search, forward checking, arc consistency, MRV / degree / LCV ordering, min-conflicts) never asks what a variable means. It only ever calls constraint.is_satisfied(assignment). It cannot tell the difference between "two queens share a diagonal" and "two exams share a student" — to the solver they are the same shape.

So what's the common constraint? It is not a single rule like "all-different" — it's the predicate abstraction itself. Every concrete constraint in this project reduces to exactly two reusable shapes: BinaryRelation(x, y, predicate) for pairwise rules (not-equal, equal, right-of, next-to — N-Queens, colouring, Sudoku, the Zebra puzzle) and Predicate(variables, predicate) for n-ary rules (the column-sum-with-carry equations of cryptarithmetic). "All-different" itself is not a separate primitive — it's sugar that expands into pairwise BinaryRelation objects. One idea, instantiated with different predicates, never a different solver.

Techniques implemented

SearchSystematic backtracking (first solution and all-solutions variants)
PropagationForward checking, generic AC-3 / MAC (maintaining arc consistency)
Ordering heuristicsMinimum Remaining Values (MRV), degree heuristic, Least Constraining Value (LCV)
Local searchMin-conflicts — repairs a complete, inconsistent assignment instead of building one incrementally
ReductionExam scheduling is solved by reducing it to graph colouring — zero new solver code

N-Queens

variables = columns · domains = rows · constraints = NotEqual(row) and NotEqual(diagonal) between every pair of columns

Map / Graph Colouring

variables = regions · domains = colours · constraints = NotEqual between every pair of adjacent regions

Sudoku

variables = cells · domains = 1-9 · constraints = all_different(row), all_different(column), all_different(box)

Click a cell and type 1-9 to edit the puzzle before solving. 0 / blank = unknown.

Cryptarithmetic

variables = letters (+hidden carries) · domains = digits 0-9 · constraints = all_different(letters) + one column-sum predicate per digit column

Naive backtracking is intentionally slow here (that's the point of the Benchmark tab) — pick an algorithm with MAC/MRV for a fast answer.

The Zebra / Einstein Puzzle

variables = (category, value) pairs · domains = house 1-5 · constraints = all_different per category + 10 relational clues (SameHouse / RightOf / NextTo)

Exam Scheduling — reduced to graph colouring

No new solver code: two exams sharing a student become an edge; time slots become colours; the SAME graph-colouring CSP builder is reused.

Custom CSP Playground

This is the proof, not a toy: type ANY (variables, domains, constraints) description and it is handed to the identical solver above, through csp_engine/web/custom_csp.py, which builds the CSP from nothing but BinaryRelation, Predicate and all_different — the same primitives every preset problem on this page uses.

Constraint types: not_equal, equal, less_than, greater_than (binary), all_different, sum_equals (n-ary, needs a numeric target).
